# summarizer

FastAPI-сервис для получения краткой выжимки из документов в формате PDF,
которые скачены с сайта госзакупок, с использованием LLM.

## Возможности

- Принимает PDF-файл и возвращает **структурированный JSON**:
  - сумма контракта (`amount`, `currency`, `raw`);
  - сроки выполнения;
  - ключевые требования к исполнителю (список);
  - список штрафов;
  - служебные поля `status` (`extracted`/`partial`) и `notes`.
- **Гибридная схема извлечения текста** в пользу экономии токенов:
  1. `pdfplumber` — программное извлечение текста;
  2. если текста недостаточно (скан) — **локальный OCR** (`tesseract` + `rus`);
  3. если и OCR не дал результата — страницы-картинки уходят в **мультимодальную модель**.
- **Универсальный вызов LLM** — OpenAI-совместимый клиент (`base_url`/`model`/`api_key`
  через конфиг): подходит для OpenAI, Claude (совместимый `/v1`), GigaChat, YandexGPT и др.
- Логирование с `request-id`, валидация входного файла, Docker-сборка.

## Старт сервиса

### Локально

Требуется Python 3.11+ и [uv](https://docs.astral.sh/uv/).

```bash
uv sync                              # создает venv по pyproject.toml + uv.lock
cp .env.example .env                 # заполните LLM_API_KEY, LLM_BASE_URL, LLM_MODEL
uv run uvicorn app.main:app --reload
```

Для работы OCR на сканах нужен системный `tesseract-ocr` с русским языком:

```bash
# macOS
brew install tesseract tesseract-lang
```

### Docker

```bash
docker compose up --build
```

Сервис слушает порт `8000`. Образ собирается на `python:3.12-slim` с `uv`,
`tesseract-ocr-rus` и non-root пользователем, включает `HEALTHCHECK`.

## Использование

Проверка живости сервиса:

```bash
curl -s http://localhost:8000/health
```

Анализ PDF:

```bash
# режим по умолчанию — local (извлечение текста через pdfplumber и tesseract OCR)
curl -F file=@tender.pdf http://localhost:8000/analyze

# принудительно отправить страницы-картинки напрямую в мультимодальную модель
curl -F file=@tender.pdf -F mode=cloud http://localhost:8000/analyze
```

Параметр `mode` (`local`/`cloud`, по умолчанию `local`):

- `local` — пробуем извлечь текст через `pdfplumber`, затем через `tesseract` OCR.
  В LLM уходит текст, медиа в модель не отправляется.
- `cloud` — страницы-картинки рендерятся и отправляются напрямую в мультимодальную
  модель (без локального OCR).

Пример ответа:

```json
{
  "contract_amount": {"amount": 1234567.89, "currency": "RUB", "raw": "1 234 567,89"},
  "deadline": "в течение 30 календарных дней с момента заключения контракта",
  "contractor_requirements": [
    "членство в СРО",
    "лицензия МЧС",
    "опыт исполнения аналогичных контрактов не менее 3 лет"
  ],
  "fines": [
    {"description": "просрочка поставки", "amount": "0,1% за каждый день", "basis": "п. 5.3 контракта"}
  ],
  "status": "extracted",
  "notes": null
}
```

## Структура

```
app/
  main.py         # FastAPI: POST /analyze, GET /health, middleware
  config.py       # Настройки (pydantic-settings)
  schemas.py      # Pydantic-модели ответа
  extract.py      # Гибридная схема: pdfplumber -> OCR -> media
  pdf.py          # pdfplumber и PyMuPDF-рендер
  ocr.py          # pytesseract OCR
  llm.py          # OpenAI-совместимый клиент (текст/vision, JSON-mode)
  logging_conf.py # Настройка логирования
  prompts/        # Шаблон промпта
```

Установите `LOG_LEVEL=DEBUG`, чтобы видеть подробный вывод

## Что можно добавить (в планах)

- **Чанкинг**: сейчас контент уходит в модель одним вызовом (текст — до `MAX_TEXT_CHARS`,
  страницы — до `MEDIA_MAX_IMAGES`). Для очень больших документов можно добавить разбиение
  на чанки и несколько вызовов LLM с последующим объединением результата.
- **Брокер сообщений**: вынести анализ в асинхронную очередь (RabbitMQ + worker).
  `POST /analyze` возвращает `job_id`, а тяжелая обработка (рендер → OCR → вызов LLM) идет
  в фоне.
- **История и статусы в БД**: хранить результаты анализа и статус обработки
  (в очереди / в работе / готово) в PostgreSQL. 
- **Другие форматы**: помимо PDF поддержать DOCX/DOC, а также XML-структуры с сайта закупок

## Ограничения

- Для скан-документов в режиме CLOUD нужна **мультимодальная** модель, поддерживающая изображения; иначе `curl` вернет `502`.
- Сервис не выполняет авторизацию и не хранит историю — только обработка одного файла.
